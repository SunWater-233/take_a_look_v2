# 固件上下文

符号变量、源码调试、FreeRTOS 和固件下载共用 `sourceProject.firmwarePath`。
这是唯一保存和传输的固件路径。`sourceRoot` 也只保存在 `sourceProject`。

后端在接收工程配置时展开 `~`、解析相对路径和 `..`，随后只保存绝对路径。
相对输入以本次提交的源码根目录为基准；没有根目录时不能输入相对路径。
修改源码目录不会改变已经确定的固件文件，也不会恢复隐藏的目录配置。
编译命令、解释器和路径只随 `.talproj` 工程保存。

## 状态与命令

`firmware` 只包含运行时元数据，不包含第二个路径：

| 字段 | 含义 |
| --- | --- |
| `status` | `empty` 未选择、`missing` 文件未生成、`ready` 已解析、`stale` 编译后保留旧符号、`unloaded` 编译后尚未解析 |
| `revision` | 每次提交解析结果时递增 |
| `fingerprint` | 实际解析字节的 SHA-256；没有解析结果时为空 |

- `loadFirmware {path, loadId?}`：显式加载或刷新，文件必须存在。
- `setSourceProject {..., firmwarePath, loadId?}`：保存配置时解析存在的固件，即使路径相同也重新解析。文件尚未生成时提交路径并清空旧符号、监视项、源码索引和 FreeRTOS 布局。
- 只修改 `sourceRoot` 或编译选项时，保持当前固件和解析结果。
- 解析或配置验证失败时，不提交新配置和解析结果。
- `startSourceTask`：只使用工程中的固件路径，没有下载路径兜底。

`services/source_project.py` 负责配置验证和路径解析。
`services/firmware.py` 负责候选解析、状态提交、监视项重绑定和下载流程。
目标操作继续使用现有探针锁，界面和独立窗口只消费提交后的状态。

## 编译和下载

编译成功不会自动更换运行目标的符号地址，而是将元数据标为 `stale` 或 `unloaded`。
两个面板显示同一提示，用户可以刷新符号或下载固件。

下载先复制文件到任务私有目录，再解析这份快照，随后烧写并校验相同字节。
解析失败不会进入烧写；烧写成功后提交已经解析的结果，工程路径始终指向原文件，
不暴露临时下载路径。烧写失败后维持原有符号并暂停采集，不宣称目标已经回滚。

常规加载在解析前后检查内容指纹，发现编译器同时覆盖文件时拒绝提交混合结果。

## 格式边界

桌面 stdio 协议为 v3，工程文件为 v2。旧命令 `loadSymbols`、旧字段 `symbolFile`、
旧工程格式和 `source-projects.json` 不再读取，没有迁移或兼容分支。
工程恢复只提交一次源码工程配置，不再单独加载另一个符号路径。

## 验证

后端回归覆盖单一路径、目录切换、同路径新内容、缺失文件清理、解析失败回滚、
编译后过期标记、烧写前解析，以及解析期间文件变化。
Flutter 集成测试通过真实 stdio 服务验证主窗口、独立窗口和工程恢复的路径一致性。
