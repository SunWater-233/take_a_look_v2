# 符号与断点加载优化（2026-11-17）

下载后的“正在加载新符号与断点”阶段包含 DWARF 类型与成员解析、源码行号及定义
索引、监视变量重绑定、断点安装，以及完整状态发布。本次优化主要处理主机上的重复计算。

## 改动

- 一个数组只解析一次元素类型及成员模板，再为各元素生成名称和地址偏移。
  多维数组、结构体数组和指针标记保留原有语义。
- 先读取 ELF 候选符号，只为名称或地址匹配的变量展开 DWARF 类型，避免为不能监视的
  栈变量和无关声明展开大量成员；地址匹配保留链接名称与 DWARF 名称不同的情况。
- 监视变量按“来源文件、变量名”建立一次索引，重绑定复杂度从 O(监视数 × 符号数)
  变为 O(监视数 + 符号数)。重名歧义仍不自动绑定。
- 每个服务只缓存最近一份成功解析的符号和源码索引，按完整文件的 SHA-256 识别。
  重复下载产生不同临时路径时仍可复用；内容变化即重新解析，与大小、时间戳是否变化无关。
  ELF 解析和摘要来自同一份内存快照。源码索引读取失败的结果不会进入缓存。
- 缓存只保存解析数据。下载之后仍重新设置目标断点、绑定监视变量，并更新工程与符号路径。
- 下载输出增加变量解析、源码索引、监视重绑定、断点设置、状态发布和总耗时。

## 实测

Windows / Python 3.11.7，同一解释器和依赖。首次解析比较使用 Git `997be0c` 中原有的
三个解析模块与当前版本，在同一进程中前后交替、各运行三次，未使用结果缓存；下面为中位数。
测量期间没有并行构建或回归测试。

| 实际输入 | 符号数 | 原解析耗时 | 新解析耗时 | 减少 |
| --- | ---: | ---: | ---: | ---: |
| wheel-leg H7_Robot.axf，1,701,084 字节 | 49,978 | 4.00 秒 | 2.53 秒 | 约 37% |
| dr_nova_demo H7_Robot.axf，2,084,900 字节 | 46,837 | 4.68 秒 | 3.27 秒 | 约 30% |

独立的监视重绑定测试中，每份输入设置 200 个监视变量，耗时分别从约 0.996 / 0.976 秒
降至约 0.015 / 0.017 秒。

同一服务重新加载相同内容、不同临时路径的固件时，缓存命中后的服务阶段约为 0.07–0.085 秒，
包含 200 个监视变量重绑定和状态对象准备。该数字不包含 stdio 编码传输、Flutter 界面刷新
或物理探针的断点写入，不代表整个下载任务耗时。

最终打包版通过实际 stdio RPC 加载 wheel-leg AXF：首次约 2.42 秒，相同内容从新暂存路径
再次加载三次为 0.479 / 0.476 / 0.468 秒。这里包含约 30 MB 的状态事件与响应传输及
Python 客户端 JSON 解码，未连接探针，也不包含 Flutter 界面呈现。原始数据为
`build/symbol-load-rpc.json`。

两份固件的全部符号字段、结构体/数组成员地址、源码定义字段和源码行地址均与旧模块比较一致。
输入 SHA-256 分别为：

- wheel-leg：`0c28963fbcde9e3be493deb4447267291f66a87ec7a95194a72221994051ff7c`
- dr_nova_demo：`e32b1738a95b1348b18da19c868e2890bc58eb6f0f0d657f7ede235b6829e624`

原始分阶段数据保存在 `build/symbol-load-before.json`、`build/symbol-load-after.json`，
前后交替的最终解析数据为 `build/symbol-load-paired.json`。
