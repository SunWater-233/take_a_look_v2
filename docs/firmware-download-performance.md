# EmberMobile 固件下载优化（2026-10-22）

本轮保持 MCU 源码和应用固件内容不变，使用已经在板上下载成功的
`2026_wheel_legged_infantry_test/chassis/MDK-ARM/H7_Robot/H7_Robot.axf`。
手机为 OPPO PEAM00 / Android 12，探针为 Horco CMSIS-DAP v2，
VID FAED / PID 4873，序列号 343420328170，目标为 STM32H723VG。

## 修改

- 私有协议下载时，本机将 ARM ELF32 的 PT_LOAD 段重新封装为精简 ELF。
  所有加载段的文件字节、虚拟地址、物理加载地址、内存长度和权限保持不变；
  为 probe-rs 保留加载节。调试信息和符号继续从原始 ELF 在电脑加载。
  更小的文件没有收益时使用原始文件；其他 ELF 类型沿用原始上传。
- 手机 FlashLoader 启用实际读回比较，按擦除扇区跳过内容相同的部分。
  只比较固件覆盖的字节，不能拿 FF 去比较需要保留的空隙。
  一个扇区有任何差异就保留完整擦写计划，保留未写入字节并完整校验。
  比较失败立即报错，在擦除之前终止。
- 比较优化只在保留未写入字节、扇区擦除模式下使用。
  全片擦除、跳过擦除和跨扇区 Flash 页保留原有行为。
  原生私有协议及 Ember GDB 的 vFlash 提交共享这项优化。
- 下载日志显示实际上传字节、上传耗时及手机比较/擦写/校验耗时。
  没有通过关闭校验、整片擦除或覆盖未写入区域来提速。

## 实测基线

原始 AXF 为 1,685,992 字节，实际加载数据 139,408 字节。
精简后的 ELF 为 139,632 字节，所有加载段已逐字节比对相同。

| 阶段 | 优化前 | 优化后 |
| --- | ---: | ---: |
| Wi-Fi / QUIC 上传文件 | 3.107 秒 | 0.233 秒 |
| 上传及 SHA-256 就绪确认 | 3.166 秒 | 0.264 秒 |
| 手机重复下载相同固件（含实际读回比较） | 12.307 秒 | 约 1.34–1.40 秒 |

旧版重复写入完全相同固件，手机操作仍约 12.307 秒：
填充保留区约 1.3 秒、擦除约 3.5 秒、编程约 5.2 秒、校验约 2.3 秒。
两个 128 KiB 扇区共擦写 262,144 字节，其中固件未覆盖、需要保留的部分为 122,736 字节。
阶段切换时间来自轮询，有约 0.2 秒的测量粒度。

新版手机实际返回 `Preverify skipped 2 unchanged sectors`，任务成功，恢复运行。
源码后端包含上传及手机作业约 2.15 秒；最终 Windows 打包后端通过实际 stdio
执行下载任务，传输 136.4 KiB / 0.57 秒、手机比较 1.40 秒，随后重载原始
AXF 的符号并恢复目标运行，总计约 5.45 秒。传输受 Wi-Fi 瞬时状态影响。
这不是首次烧录的耗时，也不是同等大小新固件的完整擦写耗时。

重复下载的收益依赖实际相同的扇区数量；首次烧录或全部扇区都变化时仍需完整擦写。
精简上传当前适用于 EmberMobile 私有协议下载；GDB/MI 下载仍使用原始文件及其校验路径。

原始日志位于本机 build/ 下：`firmware-baseline-phone.log`、
`firmware-upload-before-after.log`。它们不属于产品运行所需文件。
新版实测见 `firmware-optimized-phone.log` 和 `firmware-optimized-packaged.log`。

## 验证

Rust 测试覆盖完整相同内容、部分变化、保留区及索引重排、读取失败和跨扇区页。
Python 测试覆盖真实 ARM ELF 的加载段/LMA 保真、SHA-256 上传、异步烧录失败、
写后回读失败、完整服务下载及 GDB 下载回归；打包后端也通过自检。
