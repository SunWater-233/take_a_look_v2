# 长时间窗绘图与采样记录管线优化

在持续追加样本并滚动显示时，原来的极值缓存会因数据版本和视窗变化失效，跨页查询仍逐页访问。此次增加跨页范围树，按脏页更新极值，并让暂停快照共享索引，在需要修改摘要时才复制。

后端把待提交批次、采集策略快照、背压、提交计数、错误传播和导出屏障集中到 `SamplePipeline`。记录与传输共用封存的样本批次，减少重复列表和逐样本策略查询。历史索引在一次遍历中生成 64 点摘要，以完整块写入无用户态缓冲的文件；短写会继续完成，零进展或异常会停止提交。文件长度仍立即反映完整写入，不引入定时延迟、预分配或新文件格式。

修复了部分可见变量行被裁剪后提示框偏移的问题：裁剪只判断可见性，提示框使用完整行中心。滚动测试同步适配现有的独立采集区与成员区，分别验证部分裁剪对齐和成员区离屏回退。源码导航的返回/前进栈也有了独立状态所有者，保留 100 条历史、分支清理和视图重置行为。

## 同条件结果

基线是 Git `00951573434c7e783a18b418bc72d70c0f9ca260` 的源码归档。两边使用同一 Flutter、Python、依赖版本、机器和基准输入。有效性能测试顺序执行，未与构建或回归测试并行；前后顺序交替。精确数据、源文件哈希和验证记录见 [results.json](results.json)。

60 秒图窗的 CPU 绘图 P95 从 17.39–18.39 ms 降至 8.52–8.54 ms。它接近评估时提出的 8 ms 目标，但尚未低于该目标。基准中的 P95 来自校准后的测量块平均耗时分布，不是实际显示器的逐帧延迟。

暂停 32 通道图表约需 0.87–1.23 ms，避免了立即复制整棵极值索引。跨页索引在每通道 60 万点的配置下增加约 192 KiB/通道，即 32 通道约 6 MiB；快照共享这部分存储，后续修改时才复制。

后端三轮的 10 kHz 设置下，修改前范围为 6102–7428 Hz，修改后为 6755–7723 Hz，不能据此宣称稳定跑满 10 kHz。CPU 中位数在 1 kHz 设置下由约 0.276 核变为 0.328 核，在 10 kHz 设置下由 1.108 核变为 1.140 核；本次没有证明端到端采样的 CPU 消耗下降。固定工作量记录器的 CPU 降低需要与这组调度结果区分。

真实图表/监视/分析 Widget 加 FFT 的隐藏窗口合成测试中，前后两版的模拟输入均约 10 kHz，所有已投递帧的缓存计数一致。修改前后 raster P95 分别约 18.75 ms 和 18.60 ms，GPU 绘制没有明显变化。这次主要改善长时间窗的 CPU 查询和绘图准备，未更换渲染器或降低曲线质量。

## 行为与格式验证

- 随机范围与列表参考实现逐点比较，覆盖跨页、环形回绕、重复时间、同值极值的最早位置、写入后失效、脏索引快照、扩容和清空。
- 冻结样本与索引均使用写时复制，后续采样不能修改旧快照。
- 队列满时保留待提交数据，记录完成后才发布样本；写入失败只报告一次且不发布未提交样本。
- 采集策略在入队时封存。后续修改监视/手动策略不能追改旧数据，空批次或被过滤的值不能更新旧数据的新鲜度时间戳。
- 完整块写入覆盖短写与零进展；历史写入失败不能推进原始记录的导出边界。
- 12291 帧兼容性负载包含稀疏通道、重复和乱序时间、同值极值、布尔值、非数值间隙与 transaction_window 元数据。修改前后产生的原始日志、历史索引、清单及 CSV 共 12 个文件逐字节一致。
- 目标操作继续由原有锁串行执行；采样截止时间、显式写入回读、导出、轮转、断线及停止顺序保留。

## 复现

```powershell
# 图表基准；另用 -SourceRoot 指向基线源码，保持依赖版本一致。
.\tool\run_data_benchmarks.ps1 -Suite audit -Runs 2 -ResultSet chart-check
.\tool\run_data_benchmarks.ps1 -Suite live -Runs 1 -ResultSet chart-check -SkipBuild

# 后端调度、解码、记录及内部事件交付，包含最终排空和并发写入回读。
.\backend\.venv\Scripts\python.exe tool/benchmarks/backend_throughput.py --source-root . --output build/backend-check.json --runs 3 --seconds 3 --rates 1000,10000

# 固定记录工作量，排除采样定时器和探针开销，包含 close/fsync。
.\backend\.venv\Scripts\python.exe tool/benchmarks/recording_throughput.py --source-root . --output build/recording-check.json --runs 2 --batches 640
```

基准运行器会记录全部 Dart 源文件哈希，检测增删文件，并将输出重定向到日志，以便复查构建来源和隐藏窗口退出情况。本次完整原始数据保留在 `build/optimization-20261026/`；有效轮次以 `audit-final-*`、`live-final-*`、`backend-final-*`、`recording-final-*` 命名，较早的诊断轮次不用于上表。

## 验证边界

图表数字使用 Windows Release AOT，包含持续追加、自动 Y 轴、精确极值与 CPU 绘图，排除 GPU。隐藏窗口 live 测试仅代表引擎工作，不证明真实显示呈现帧率。后端使用返回原始字节的模拟目标，包含生产解码、调度、原始记录、历史索引及内部事件交付，不包含 USB/SWD、网络、stdio 管道或 UI。已采集、已记录及已交付计数一致，不表示每个请求采样周期都已实现。

本次没有物理探针、手机网络或 MCU 验证；这些短时基准也不证明长时间稳定性。
